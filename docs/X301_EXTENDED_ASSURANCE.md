# X301 extended assurance lane

Date: 2026-08-25

This lane is additive to T1-T13.  It adapts Wycheproof and OpenSSL test
taxonomies to X301, exercises X301MLKEM1024 on the wire, and adds bounded
fuzzing substitutes and long-running targets.  It does not alter the X301
byte contract, add production dependencies, or import X25519/X448 expected
bytes.

## Reproducible entry points

```sh
python3 -I -B -O reference/x301/generate_adversarial_corpus.py --check
python3 -I -B -O reference/x301/test_x301_reference.py

scripts/test-x301-provider-contracts.sh \
  OPENSSL_3_5_7_ROOT OPENSSL_3_5_7_EVIDENCE_SHA256 \
  OPENSSL_4_0_1_ROOT OPENSSL_4_0_1_EVIDENCE_SHA256

scripts/test-x301-tls.sh \
  OPENSSL_3_5_7_ROOT OPENSSL_3_5_7_EVIDENCE_SHA256 \
  OPENSSL_4_0_1_ROOT OPENSSL_4_0_1_EVIDENCE_SHA256

X301_TLS_LONG_HANDSHAKES=1000 scripts/test-x301-tls.sh \
  OPENSSL_3_5_7_ROOT OPENSSL_3_5_7_EVIDENCE_SHA256 \
  OPENSSL_4_0_1_ROOT OPENSSL_4_0_1_EVIDENCE_SHA256
```

`scripts/check.sh`, `scripts/check-secret-taint.sh` and
`scripts/check-x301-long.sh` deliberately require an externally anchored,
read-only archive snapshot.  This prevents an authoritative gate from
silently testing a writable or incomplete source tree.

The W corpus contains 559 total cases and is generated byte-identically as
both JSON and a C header.  The P1-P4 and 10,000-case differential tests are
mandatory in `scripts/check.sh`, even though their Rust test functions remain
ignored for an ordinary developer `cargo test`.

The initial L1 computation took 1,263.28 seconds in the independent
standard-library Python oracle and 94.59 seconds in the release Rust core.
Those durations describe this execution host only; the acceptance condition
is the common 38-byte result, not timing.

## Fuzzing boundary

Neither `cargo-fuzz` nor AFL++ was installed in the execution environment.
The specified fallback was therefore selected, not silently weakened:

- raw X301 lengths 0 through 76;
- every deletion and insertion position;
- every byte value at every position of a valid 38-byte private/public key;
- hybrid lengths 0 through 1607;
- every bit of a valid 1,606-byte client and server share;
- every deletion and insertion position of both hybrid forms;
- the frozen W corpus before each provider-entry sweep.

This is complete for that finite grid.  It is not a claim of coverage-guided
fuzzing or an arbitrary-input proof.  ASan/UBSan instrument the C provider
boundary and harness. Stable Rust is covered separately by Valgrind, secret
taint and final-binary codegen review; no unsupported Rust sanitizer claim is
made.

## Evidence boundary

The externally sealed result bundle records the final source-manifest digest,
local Git commit, toolchain identities, exact OpenSSL lane evidence digests,
module hashes, commands, compact logs and status files. Historical PASS logs
or an unanchored worktree do not substitute for that bundle.
